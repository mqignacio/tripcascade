## Dimension 2: Controlled Execution (Score: 90/100)

**What it measures:** Determinism, error handling, step budgets, give-up mechanisms, and non-LLM control flow for money operations.

| Criterion | Evidence | Score |
|---|---|---|
| Step budget + give-up | `orchestrator.py` has `step_budget` and `_give_up()`; tested in `test_e2e_step_budget_gives_up` (test_agent_core.py) | 10/10 |
| Re-read before write | `policy._assert_live_state_unchanged()` verifies live fare before every write; `StaleStateError` raised on drift; tested in `test_reread_before_write_fare_drift` and `test_reread_before_write_prevents_double_pay` | 10/10 |
| False-success cure | `FalseSuccessError` raised when post-state (orderNo, payment_confirmation_id) is empty despite HTTP 200; tested in `test_false_success_empty_orderno` | 10/10 |
| Deterministic policy (no LLM money) | `policy.build_atlas_call_body()` is pure deterministic code — LLM never constructs the Atlas call body; tested in `test_fr006_no_llm_transaction_body` | 10/10 |
| LLM proposal scope | LLM only proposes *which* alternative + rationale; fare difference computed from prices, never generated by LLM | 10/10 |
| Both policy paths tested | Auto ≤ cap (tested), human > cap (tested), human rejection (tested), advisory (tested) | 10/10 |
| **Deductions** | -10: The policy engine uses `StubAtlasClient` for deterministic testing. The real `CLISubprocessClient`/`RestClient` paths are only exercised manually (live Sandbox test is skipped unless CLI is authed). A `StaleStateError` or `FalseSuccessError` from a real API call is only tested via stubs, not live. | 90 |

**Remediation:** Add a live integration test that exercises `StaleStateError` and `FalseSuccessError` against the real Sandbox with a deliberate stale/missing state. This is a stretch goal (P1) — the stub tests provide the deterministic coverage.

## Dimension 3: Change Validation (Score: 80/100)

**What it measures:** Test coverage, assertion depth (real outcomes vs status codes), regression detection, and CI readiness.

| Criterion | Evidence | Score |
|---|---|---|
| Acceptance test coverage | 28 tests in `test_acceptance.py` mapping all 10 FRs + 55 other tests across 4 test files = 83 total (1 skipped) | 10/10 |
| Real-outcome assertions | Tests assert `orderNo` non-empty, `asserted=True`, decision log records exist with correct outcomes — never just HTTP 200 | 10/10 |
| Stale-state + false-success regression | Dedicated tests verify both error types are raised | 10/10 |
| Deterministic test data | Demo itinerary seed (`assets/demo_itinerary.json`) is fixed; stub client is deterministic | 10/10 |
| E2E scenario | `test_e2e_scenario.py` runs the full flow as a standalone script; `test_e2e_full_scenario` in pytest | 10/10 |
| **Deductions** | -20: (1) No CI pipeline configured (GitHub Actions, etc.) — tests must be run manually via `uv run pytest`. (2) No coverage tracking — no `coverage.py` or `pytest-cov` configured. (3) The E2E scenario is tested on stubs, not live Sandbox. (4) No performance/stress tests. | 80 |

**Remediation:**
- Add GitHub Actions workflow (`.github/workflows/ci.yml`) to run `uv run pytest -q` on push/PR
- Add `pytest-cov` to dev dependencies and a `coverage` config
- The live-Sandbox gap is acceptable (Sandbox rate limits + no CI secrets)
